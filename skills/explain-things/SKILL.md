# Explain Things (Analogy + Visual Diagram + Concrete Example)

Explains any code, spec, architecture, or concept so simply that anyone can understand it in under 60 seconds, using **everyday analogies**, **visual Unicode diagrams**, and **concrete real-world examples**.

---

## Strict Rules

> [!IMPORTANT]
> 1. **STRICTLY READ-ONLY**: Never create, modify, or delete project code or specification files.
> 2. **IN-CHAT VISUALS**: Never output raw unrendered Mermaid code blocks. Use **Unicode Box-Art** (`┌─┐`, `│`, `└─┘`, `▼`, `►`) directly in the chat window so the visual renders immediately.
> 3. **CONCRETE EXAMPLES**: Always ground the concept with a realistic side-by-side comparison or real numbers (e.g., Scenario A vs. Scenario B).

---

## The 4-Part Explanation Formula

Every response MUST follow these 4 sections:

### 💡 1. The Everyday Real-Life Analogy
* Connect the concept to a familiar everyday object or experience (e.g., TV picture presets, restaurant reservations, airport boarding groups, highway express lanes).
* Explain *why* it exists in 2–3 clear, simple sentences without technical jargon.

---

### 📊 2. In-Chat Visual Flow (Unicode Box Diagram)
* Draw a clean, visual box-and-arrow diagram directly in the chat.
* Show *Input $\rightarrow$ Decision $\rightarrow$ Result* or *Without vs. With*.

```text
  User Action ──► [ Decision Point ] 
                         │
           ┌─────────────┴─────────────┐
           ▼                           ▼
    [ Outcome A ✅ ]            [ Outcome B ❌ ]
```

---

### 🏢 3. Concrete Real-World Example (Side-by-Side Table)
* Provide 2 contrasting real-world scenarios comparing how the concept behaves in practice with actual values (e.g., numbers, times, permissions).

| Setting / Field | 🏥 Scenario A (e.g., Walk-In Clinic) | 🧠 Scenario B (e.g., Therapy Clinic) |
| :--- | :--- | :--- |
| **Real Need** | Needs instant, same-day access | Needs advance prep & client triage |
| **Applied Value** | `0 minutes` notice | `24 hours` notice |
| **Result** | Auto-confirmed on the spot | Manual review + Initial Consult first |

---

### 🔑 4. Key Takeaways
* **Speed/Benefit**: What problem does this solve?
* **Safety/Rule**: What invariant does it protect?
* **Flexibility**: Can it be overridden or adjusted?
